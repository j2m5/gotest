# Auth Implementation Plan

> **For agentic workers:** Use the agreed interfaces from the spec. Implement with tests first; independent adapters may be delegated, integration stays with the root agent.

**Goal:** Repair and decouple registration, verification, sessions, and mail delivery.
**Architecture:** auth service owns rules; db owns atomic persistence; handlers own HTTP; mailer owns transport.
**Tech Stack:** Go 1.26, pgx/v5, bcrypt, React/TypeScript, existing Axios.
**Spec:** ../specs/2026-10-25-auth-design.md

## Global Constraints
- Existing server-side cookies and PostgreSQL remain.
- Mail drivers are local and smtp; local output is gitignored.
- No actual email delivery or mutation of the existing database during development.
- Existing frontend forms and current user changes remain the base.
- No new production dependencies.

## Review Focus
- Concurrent resend/verify must not deadlock or permit reusing a token.
- SMTP failure must not disguise whether the user was created.
- Expired or revoked session must not authenticate, including at exact expiry.
- Untrusted origin, malformed JSON, and oversized bodies must fail before side effects.
- Migrating existing tokens must preserve their validity only until their bounded expiry.
